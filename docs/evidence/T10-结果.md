## 安装器执行边界

- `ForgeInstallerService` 已实现：
  - Forge Maven 与 NeoForge Maven 的固定版本 installer URL；
  - 读取官方 SHA-1 sidecar，拒绝缺失/非法摘要；
  - 经 `IArtifactDownloader` 下载到 staging；
  - `ProcessStartInfo.ArgumentList` 执行 `java -jar installer.jar --installClient <stage>`，不经过 shell；
  - 10 分钟超时、进程树终止、stdout/stderr 收集、非零退出结构化错误。
- `IInstallerProcessRunner` 可注入，测试覆盖 Forge/NeoForge URL、摘要、参数和失败退出。
- `ForgeStagingMerger` 已实现 installer staging 的 `libraries/` 与 `versions/` 合并：
  - 逐文件复制，不覆盖共享目录；
  - 目标已存在且 SHA-256 相同则跳过；
  - 目标已存在但内容不同则 `LOADER_STAGING_CONFLICT`，不改旧文件；
  - 拒绝越界相对路径。
- 测试覆盖正常合并、幂等跳过和冲突拒绝。
- `ForgeInstalledVersionProvider` 已实现从共享 `versions/` 读取 installer 生成的 Forge/NeoForge 版本 JSON：
  - 校验 `inheritsFrom` 等于实例基础版本；
  - 按 loader 版本匹配 id；
  - 计算版本 JSON SHA-1；
  - 缺失时返回 `LOADER_NOT_INSTALLED`；
  - 已在桌面组合根注册 Forge 与 NeoForge 两个 provider。
- 测试覆盖版本 JSON 读取和缺失错误。
- 真实安装尚未串联：没有调用 installer + merger + provider 的 workflow，没有实际 Forge/NeoForge 启动。
