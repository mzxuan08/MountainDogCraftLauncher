## 已完成

- `LocalModService`：扫描 `mods/*.jar` 与 `*.jar.disabled`，读取 Fabric/Forge 元数据，启用/禁用时获取实例租约；运行中修改返回 `INSTANCE_BUSY`。
- 桌面已接入本地模组列表、刷新和启用/禁用。
- `ForgeInstallerService`：
  - Forge/NeoForge 固定版本 installer URL；
  - 官方 SHA-1 sidecar 校验；
  - staging 内 `launcher_profiles.json`、基础版本 JSON、client jar 预置；
  - `-Djava.io.tmpdir=<staging>/tmp`；
  - `ArgumentList` 执行 `java -jar installer.jar --installClient <stage>`；
  - 超时、进程树终止、stdout/stderr 与非零退出结构化错误。
- `ForgeStagingMerger`：逐文件合并 `libraries/`、`versions/`，SHA-256 相同跳过，冲突返回 `LOADER_STAGING_CONFLICT`，拒绝越界路径。
- `ForgeInstalledVersionProvider`：从共享 `versions/` 读取安装后的版本 JSON，校验 `inheritsFrom` 与 loader 版本，计算 SHA-1。
- `LauncherWorkflow.InstallForgeAsync`：Java 选择 → installer → 官方基础 JSON 写回 → staging 合并 → 版本解析 → 保存实例/resolved-version。
- 桌面“加载器”页提供 Forge / NeoForge 独立安装命令。

## 真实 Forge 验收

环境：Windows x64，Java 17.0.4，Minecraft 1.20.1，Forge 47.2.0。

流程：

1. 通过桌面创建 `1.20.1` 实例并完成 Mojang 原版安装。
2. 在“加载器”页输入 `47.2.0` 并点击“安装 Forge”。
3. 安装成功，实例 manifest 更新为 `forge / 47.2.0`，共享目录生成 Forge 版本 JSON。
4. 点击“启动”，游戏真实进入 Forge 主菜单：
   - 窗口标题 `Minecraft Forge* 1.20.1`；
   - 左下角 `Forge 47.2.0`、`Minecraft 1.20.1`、`MCF 20230612.114412`、`2 mods loaded`；
   - 退出游戏后 MDCL 检测到进程结束。

证据：

- `T10-forge-main-menu.log`
- `T10-forge-installer-success.log`

## 本次修复的真实问题

- staging 缺 `launcher_profiles.json`，installer 拒绝运行。
- installer processor 在受限系统临时目录创建临时文件夹失败；改为 staging 内 `tmp/`。
- 只给 installer 最小基础 JSON 时，生成信息不足；改为写回 Mojang 原始基础版本 JSON。
- classpath 使用 `client.jar`，Forge 的 `ignoreList` 只匹配 `${version_name}.jar`；改为优先基础版本 jar。
- `${version_name}` 被填成 Forge 版本 ID，导致 ignoreList 未命中原版 jar；改为基础游戏版本。
- 以上两点由 `LaunchPlanBuilder` 回归测试覆盖。
