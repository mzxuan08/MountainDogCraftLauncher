## 真实启动阻塞（F03/F04 未通过）

启动 Fabric 后，Fabric Loader 0.20.1 和 0.16.14 均在同一位置失败：

```text
RuntimeException: error remapping game jars
Caused by: java.io.IOException:
the jar file ...\.minecraft\.fabric\remappedJars\minecraft-1.20.1-0.xx\client-intermediary.jar.tmp
can't be written
at net.fabricmc.loader.impl.lib.tinyremapper.OutputConsumerPath.<init>
```

错误截图：`T09-fabric-remap-blocked.png`。

复现边界：
- 0.20.1 与 0.16.14 均失败；
- 长工作区路径与短物理 `F:\mdcl-live2` 均失败；
- 清空 `.fabric/remappedJars` 后仍失败，会留下 22 字节空 zip 临时文件；
- 将游戏目录放到 C: 时，Fabric 先在创建 `C:\mdcl-game\fabric\.fabric` 处 AccessDenied（当前执行环境限制）；未取得有效 C: remap 结果；
- 独立 Java 程序直接调用同一个 Fabric `OutputConsumerPath.Builder` 对同一路径可以成功，故尚未能归因到 MDCL LaunchPlan/classpath，也没有把它误报为已解决。

## 后续定位建议

已进一步排除 JDK 版本：Temurin `17.0.20.1+1` 下 Fabric 0.16.14 仍在 `OutputConsumerPath` 创建 `.tmp` ZIPFS 时失败，错误与 17.0.4 相同。独立诊断已确认：同一 JDK 17、同一 Fabric Loader 0.16.14、同一 `.tmp` 路径，直接调用
`OutputConsumerPath.Builder(path).assumeArchive(true).build()` 可以成功，故路径长度、扩展名和 JDK ZipFS 均不是充分原因。详见 `T09-remap-诊断.md`。失败只出现在 Fabric 游戏进程内，下一步需在游戏 JVM 内诊断 ZipFS 状态/锁/classpath 差异，或用标准启动器同机复现。当前不加入私有绕过或伪造已 remap jar。
