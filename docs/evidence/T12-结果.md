# T12 结果（验签、替换与回退核心完成；正式更新链未完成）

- 日期：2026-10-25
- 命令：`dotnet test tests/MDCL.Integration.Tests -c Release --filter FullyQualifiedName~Update`
- 结果：9/9 通过（验签 4、替换/回退 2、检查下载 2、发布侧 PEM 验签 1）。

## 已完成

- `UpdateManifest` 固定字段：version、channel、RID、HTTPS 包地址、大小、SHA-256、过期时间、最低启动器版本。
- `UpdateManifestVerifier` 在业务解析前执行 RSA-PSS/SHA-256 验签；签名覆盖规范化 manifest 字节。
- 拒绝：签名错误、过期、通道不符、RID 不符、非 HTTPS 包、非法 SHA-256、未授权降级。
- 更新包下载后再次核对 SHA-256。
- 测试覆盖：有效签名、篡改、过期、错 RID、降级、包摘要错误。

## 替换与回退

- `UpdateInstaller`：验证包摘要 → 安全解压到目标邻接 staging → 检查桌面入口 → 旧目录移入备份 → 新目录原子进入目标；失败恢复旧目录。
- `RollbackAsync`：新目录移出、备份目录恢复，失败时不删除当前目录。
- 独立 `MDCL.Updater` CLI 已加入解决方案，支持 `apply`/`rollback`，状态写入 `mdcl-update-state.json`。
- 更新器已随三 RID 自包含发布，Windows 包内位于 `updater/MDCL.Updater.exe`。
- 测试覆盖：应用新版本、旧版本备份、显式回滚、坏包摘要拒绝且旧目标不变。

## 发布侧验签

- `MDCL.Updater verify` 已实现，用于发布前用 PEM 公钥验证签名清单：
  `verify --envelope <json> --public-key <pem> --channel <c> --rid <rid> --current <version>`
- `UpdateReleaseVerifier` 支持从 PEM 导入公钥，复用 `UpdateManifestVerifier` 的版本、通道、RID、过期和 RSA-PSS 校验。
- 测试覆盖有效签名与篡改清单拒绝。

## 检查与下载

- `UpdateCheckService` 已实现：
  - 仅 HTTPS 清单 URL；
  - 先验签、再决定是否发起包下载；
  - 包大小与清单一致；
  - 下载到有界缓存临时文件，SHA-256 校验后原子移动到最终文件名；
  - 篡改清单时不请求更新包。
- 测试覆盖正常下载和篡改清单阻断。

## 未完成

- 更新器尚未进入发布包，未实现等待主程序退出的进程协调和健康检查。
- 没有三目标实际升级/回滚测试；R07、R08 未验收。
- 当前是“验签 + 替换/回退核心”，不宣称自动更新已可正式使用。
